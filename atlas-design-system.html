Atlas Design System

The single source of truth behind ~70 screens and 17 modules — tokens, type, and reusable components that let a small team ship a consistent, trustworthy product. Every example below is rendered live from the same rules the product uses.

Principles

Usage principles

The rules that keep ~70 screens feeling like one product.

Do

One primary (blue) action per view. Everything else is ghost or subtle.

Don't

Stack multiple filled blue buttons — it removes the visual hierarchy.

Do

Use status color by meaning — green=clean, amber=review, rose=error, blue=info.

Don't

Use rose or green decoratively. Color carries meaning here.

Do

Set data — GL codes, IDs, amounts — in DM Mono so it reads as exact.

Don't

Put long body copy in the serif. Reserve it for headings and figures.

Do

Replace native alert/confirm with atlasConfirm / atlasAlert.

Don't

Ship browser-default popups — they break the visual system and trust.
